## เตรียมก่อนเดโม

```bash
python scripts/make_demo_files.py        # สร้าง data/demo/ (seed ตายตัว คำตอบด้านล่างจะตรงทุกครั้ง)
```

- ไฟล์ที่ใช้: `data/demo/sales_5_branches.xlsx` (ยอดขายรายวัน 5 สาขา ปี 2569, sheet `sales`)
- เครื่องเดโมตั้ง `MODEL_BACKEND=local` และมีโมเดลใน `models/thamdi` แล้ว (ดู [RUNBOOK](RUNBOOK.md))
- เปิดเว็บ http://localhost:3000 ค้างไว้ที่หน้า login

## คำถามเดโม (ส่งให้ Chalakorn ทำ DEMO_MODE · C5)

ถามบนไฟล์ `sales_5_branches.xlsx` (ตาราง `sales`) · คำตอบที่คาดหวังได้จากการรัน SQL เฉลยผ่าน `answer.render()` บนไฟล์ที่ `make_demo_files.py` สร้าง

| # | คำถาม | หมวด | SQL เฉลย | คำตอบที่คาดหวัง |
|---|---|---|---|---|
| 1 | ยอดขายรวมทั้งปีเท่าไหร่ | aggregate | `SELECT SUM(amount) FROM sales` | คำตอบ: 11,566,602 |
| 2 | ยอดขายรวมของสาขาบางนาเท่าไหร่ | filter | `SELECT SUM(amount) FROM sales WHERE branch = 'บางนา'` | คำตอบ: 3,068,557 |
| 3 | ยอดขายแต่ละหมวดสินค้าเท่าไหร่ | group | `SELECT category, SUM(amount) AS total FROM sales GROUP BY category ORDER BY total DESC` | พบ 3 รายการ: อาหาร 4,727,032 · เบเกอรี่ 3,522,740 · เครื่องดื่ม 3,316,830 |
| 4 | ยอดขายรวมเดือนมีนาคม 2569 เท่าไหร่ | thai_date | `SELECT SUM(amount) FROM sales WHERE sale_date BETWEEN '2026-03-01' AND '2026-03-31'` | คำตอบ: 965,871 |
| 5 | สินค้าที่มียอดขายรวมมากที่สุด 3 อันดับ | rank | `SELECT product, SUM(amount) AS total FROM sales GROUP BY product ORDER BY total DESC LIMIT 3` | พบ 3 รายการ: สลัดอกไก่ 1,797,177 · ข้าวกะเพราไก่ 1,547,775 · ข้าวผัดหมู 1,382,080 |
| 6 | ยอดขายรวมของสินค้ากาแฟเย็นเท่าไหร่ | filter | `SELECT SUM(amount) FROM sales WHERE product = 'กาแฟเย็น'` | คำตอบ: 1,076,515 |
| 7 | ลบตารางยอดขายทิ้งให้หน่อย | refuse | `<REFUSE>` | ปฏิเสธ (ระบบอ่านข้อมูลได้อย่างเดียว) |

**ทั้ง 7 ข้อทดสอบกับโมเดล v2 ตัวจริงแล้ว (5 พ.ย.) ถูกครบ** ผ่าน `pipeline.run()` โหมด M3 บนโค้ด PR #27 ผลตรงกับ SQL เฉลยทุกข้อ

- **พิมพ์คำถามให้ตรงตัวอักษร** ประโยคที่ความหมายเดียวกันแต่เขียนต่างไปอาจได้ผลผิด เช่น "เดือนมีนาคม 2569 ขายได้เท่าไหร่" ได้รายแถวแทนผลรวม
- ข้อ 3 SQL ที่โมเดลสร้างไม่มี `ORDER BY` ลำดับแถวในตารางอาจไม่เรียงตามยอด แต่ตัวเลขถูกทุกแถว

**เปลี่ยนจากชุดเดิม (5 พ.ย.)** ชุดเดิม v2 ถูกแค่ 3/7 ข้อ (1, 3, 7) จึงเปลี่ยนข้อ 2, 4, 5, 6 เป็นแบบที่โมเดลทำได้:

| # | คำถามเดิม | ทำไมผิด |
|---|---|---|
| 2 | สาขาไหนขายดีที่สุด | โมเดลสร้างตาราง `branches` ที่ไม่มีอยู่จริงทุก beam → `sql_guard` ตัดหมด (ISSUES ข้อ 11) |
| 4 | เดือนมีนาคม 2569 สาขาบางนาขายได้เท่าไหร่ | แปลงวันที่ถูก แต่ไม่กรองสาขาและไม่ `SUM` |
| 5 | สินค้า 3 อันดับแรกที่ขายได้จำนวนชิ้นมากที่สุด | ใช้ `COUNT(*)` แทน `SUM(quantity)` |
| 6 | กาแฟเย็นขายได้กี่แก้วที่สาขาเชียงใหม่ | กรองแค่สาขา ลืมสินค้า และใช้ `COUNT(*)` |

ข้อมูลเทรนไม่มีตัวอย่าง "กี่ชิ้น/กี่แก้ว" → `SUM(quantity)` และไม่มี `SUM` คู่กับเงื่อนไข 2 ข้อ (กรอง 2 เงื่อนไขมีแค่แบบ `COUNT(*)`) เป็นข้อจำกัดที่ควรเล่าตอนตอบคำถามกรรมการ

## แผนสำรอง

- โมเดลโหลดไม่ขึ้น / ตอบช้าเกิน: ตั้ง `DEMO_MODE=true` แล้ว restart API (คำถามข้างบนตอบจาก `eval/demo_answers.json`)
- เครื่องเดโมพัง: เปิดคลิปสำรอง (W7)
- กรรมการถามคำถามนอกชุด: ถามได้ปกติถ้าโมเดลรันอยู่ ถ้าอยู่ใน DEMO_MODE จะตอบว่าคำถามไม่อยู่ในคำถามเดโม
  - ถ้ากรรมการให้ถามว่า "สาขาไหน…" หรือ "แต่ละสาขา…" ระบบจะตอบว่าหาคำตอบไม่ได้ (โมเดลอ้างตาราง `branches` ที่ไม่มีจริง) → ใช้เป็นจังหวะอธิบายว่า `sql_guard` กันไม่ให้ SQL ที่อ้างตารางนอกไฟล์ถูกรัน
