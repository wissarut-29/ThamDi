## ตัวอย่างข้อผิด

### 1. JOIN `orders` ทั้งที่คำถามใช้ตารางเดียว (23 จาก 53 ข้อผิด)

- **h001** "แสดงชื่อสินค้าที่อยู่ในหมวดขนมทั้งหมด"
  - เฉลย: `SELECT name FROM products WHERE category = 'ขนม'`
  - โมเดล: `SELECT products.category FROM orders JOIN order_items ... JOIN products ...`
- **h011** "แต่ละหมวดมีสินค้ากี่รายการ" → โมเดลนับแถวจาก `orders JOIN order_items` แทน `GROUP BY category` บน `products`

**สาเหตุ:** ข้อมูลเทรนของ schema แบบร้านค้าแทบทุกตัวอย่างเริ่มจาก `FROM orders JOIN ...`
โมเดลขนาด 0.5B จำรูปนี้ไปใช้กับทุกคำถาม และมักเลือกคอลัมน์ผิดด้วย (`category` แทน `name`)
**ทางแก้:** เพิ่มตัวอย่างเทรนแบบตารางเดียวบนตาราง dimension (`products`, `customers`)

### 2. แปลงปีไทยแบบย่อผิด "ปี 69" → 2069

- **h059** "ปี 69 มีการยืมหนังสือกี่ครั้ง"
  - เฉลย: `loan_date` ในช่วงปี 2026
  - โมเดล (ทุกโหมด): `loan_date >= '2069-01-01' AND loan_date <= '2069-12-31'`

ขั้นแปลงวันที่ไทยของ M1 แปลง "พ.ศ. 2568" และ "มีนาคม 2569" ได้ แต่ไม่แปลงปี พ.ศ. 2 หลักที่ตามหลังคำว่า "ปี"
โมเดลเลยอ่าน 69 เป็น ค.ศ. 2069 **ทางแก้:** เพิ่มรูป `ปี \d{2}` ใน `thai_dates` (แก้ได้โดยไม่ต้องเทรนใหม่)

### 3. ช่วงวันที่ถูกตัดเหลือเดือนเดียว

- **h024** "ตั้งแต่ 1 มิ.ย. ถึง 30 ก.ย. 68 มีคำสั่งซื้อกี่รายการ"
  - เฉลย: `BETWEEN DATE '2025-06-01' AND DATE '2025-09-30'`
  - M0/M1: ได้แค่ เดือน ก.ย. · M2/M3: ได้แค่ เดือน มิ.ย.

ข้อมูลเทรนมีแต่ "เดือน X ปี Y" ไม่มีช่วง "ตั้งแต่…ถึง…" โมเดลจึงเก็บได้แค่วันเดียวของช่วง

### 4. ไม่ปฏิเสธคำถามที่ตอบจากข้อมูลไม่ได้

- **h034** "ขอดูเงินเดือนพนักงานแต่ละคน" (ไม่มีตารางพนักงาน) → ควรตอบ `<REFUSE>`
  โมเดลกลับสร้าง `SUM(quantity * unit_price)` ต่อลูกค้า ซึ่งรันได้และได้ตัวเลขที่ดูน่าเชื่อ
- **h068** "หมอคนไหนเก่งที่สุด" → ควรตอบ `<CLARIFY>` โมเดลจัดอันดับหมอตามจำนวนนัดเอง

กรณีนี้อันตรายที่สุด เพราะผู้ใช้ได้คำตอบที่ผิดโดยไม่มีสัญญาณเตือน ในหน้าเว็บผู้ใช้ยังกดดู SQL ที่รันจริงได้
และควรเขียนเรื่องนี้ไว้ในข้อจำกัด

### 5. ค่าในเงื่อนไขผิดภาษาหรือผิดคอลัมน์

- **h036** "ผู้ป่วยผู้หญิงมีใครบ้าง" → `gender = 'female'` (ข้อมูลจริงเป็น `'หญิง'`) ได้ 0 แถว
- **h046** "นัดแต่ละสถานะมีกี่นัด" → `status = '已完成'` ภาษาจีนหลุดมาจากโมเดลตั้งต้น
- **h026** "คุณสมชาย ใจดี สั่งซื้อไปแล้วกี่ครั้ง" → `customer_id = 'คุณสมชาย ใจดี'` เอาชื่อไปเทียบกับ id (ควร JOIN `customers`)

โมเดลไม่เห็นค่าจริงในตาราง (ตั้งใจ: ค่าในเซลล์ไม่ถูกส่งเข้า prompt เพื่อกันคำสั่งแฝง) จึงต้องเดาค่าที่เป็นข้อความ

## ข้อสังเกตเรื่องตัววัด
